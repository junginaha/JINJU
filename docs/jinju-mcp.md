# 진주 ChatGPT 연결

## 구현 범위

`/mcp`는 공개 글 검색과 전문 조회를 제공하는 MCP Streamable HTTP 엔드포인트다.
기존 `getPublicPosts`를 사용하므로 공개 피드의 숨김·중복 제거·콘텐츠 교정 규칙을 공유한다.
조회 결과에는 공개 필드만 담으며 예약 글은 한 번 더 제외한다.
기존 피드는 DB 오류 시 내장 콘텐츠로 대체될 수 있다. 이 연결 역시 실시간 DB 상태를 보장하지 않는다.

- `jinju_search_posts`: 검색어, 카테고리, 최대 20개, 페이지 이동. 검색어 생략 시 최신순.
- `jinju_get_post`: 검색 결과의 ID로 전문 조회.
- 인증: 공개 자료만 제공하므로 없음.
- 직접 게시·댓글·수정·삭제: 미지원. 기존 Turnstile·검토 절차를 우회하지 않는다.

## 배포 후 연결

이 문서 작성 시 운영 배포 및 사용자 계정 연결은 완료되지 않았다.

1. 빌드·테스트를 통과한 변경을 검토하고 main에 병합한다.
2. 진주.kr 운영 배포 완료 후 `/mcp`의 초기화·도구 목록·검색·조회 응답을 확인한다.
3. ChatGPT 설정 → 보안 및 로그인 → 개발자 모드를 켠다. 계정 정책에 따라 메뉴가 없을 수 있다.
4. 플러그인 → ＋ → 이름 `진주`, 설명 `공개 글 검색과 읽기`를 입력한다.
5. MCP 서버 URL에 `https://xn--o55b9n.kr/mcp`를 입력하고 인증 없음으로 연결한다.
6. 새 대화의 도구 메뉴에서 진주 연결을 선택한다.
7. `진주 최신 글 5개 보여줘`, `북클럽 관련 글 찾아줘`, `첫 번째 글 전문을 읽어줘`로 확인한다.

주소는 배포 후 사용할 예정 주소다. GET은 405가 정상이며 브라우저에서 주소를 여는 것만으로 연결 여부를 판단하지 않는다.
ChatGPT 계정 연결과 플러그인 디렉터리 공개는 별개다. 이 변경은 디렉터리 등록 패키지나 공개 심사 완료를 의미하지 않는다.

## 검증

`node --import tsx --test tests/jinju-mcp.test.ts`

실제 MCP SDK 클라이언트와 Request/Response 전송으로 초기화, 도구 탐색, 검색, 페이지 이동, 전문 조회,
미래·없는 글 차단, 입력 검증, 내부 필드 제외, 오류, Origin 검증을 확인한다. 운영에 시험 게시물을 쓰지 않는다.

## 직접 게시의 남은 작업

기존 POST는 Turnstile 또는 검토 토큰을 요구한다. ChatGPT 사용자의 게시 권한을 검증하고
동일한 검토를 거칠 별도 인증 설계가 필요하다. AGENTS.md가 기존 보안 정책·관리자 흐름의 임의 변경을
금지하므로 이 읽기 연결에서는 해당 경로를 변경하지 않았다.

공식 연결 안내: https://developers.openai.com/plugins/deploy/connect-chatgpt
